## Moving to a maintainer team

Once 3 or more people have contributed regularly for 3 months, the project lead will invite them to form a maintainer team. Maintainers review and merge pull requests, triage issues and cut releases. Decisions then go by lazy consensus among maintainers, with the project lead breaking ties. This file will be updated when that happens.

## How decisions are made

- **Small changes** (bug fixes, docs, theme pages): one maintainer approval on the pull request.
- **Big changes** (player API, SSE events, Theme SDK API, `theme.json`, `challenge.yml`, database schema, new event formats): a public proposal in GitHub Discussions, open for at least 7 days, before code is merged.
- **Recorded decisions** go in [docs/dev/decisions.md](docs/dev/decisions.md).

## Code of Conduct

Everyone in the project follows the [Code of Conduct](CODE_OF_CONDUCT.md). The project lead (later the maintainer team) enforces it.
